## 🧪 通用 QA 测试方案

### 📌 技能目标
在 AI Agent 完成代码编写和构建后，自动执行一套标准化的功能测试流程，验证程序行为是否与项目需求文档、设计文档保持一致，并输出结构化的测试报告。

### 🧩 适用场景
- 每次代码更新并编译后。

### ⚙️ 测试执行流程（Agent 必须遵循的步骤）

#### 第一阶段：测试准备
1. **读取项目文档**：
   - 检索项目根目录下的 `README.md`、`DESIGN.md`、`SPEC.md` 或用户对话中提供的设计描述。
   - 提取其中定义的**核心功能点**、**预期输入输出**、**运行环境要求**。

2. **确定可执行入口**：
   - 找到程序的启动命令（如 `python main.py`、`npm run dev`、`./app`）。
   - 确认依赖是否已安装，若缺失则自动补全（如 `pip install -r requirements.txt`）。

3. **制定测试用例清单**：
   - 确认测试用例覆盖所有核心功能点，且包含正常流程和异常流程。
   - 如果测试用例不全面，基于文档将缺少的功能点转化为 1~3 个具体的测试用例。
   - 用例必须包含：**测试步骤**、**预期结果**、**通过标准**。

#### 第二阶段：测试执行
1. **启动程序**：
   - 在隔离的终端环境中运行程序。
   - 捕获启动日志，检查是否有明显错误（如模块缺失、端口占用）。

2. **逐项执行测试用例**：
   - 对于**命令行程序**：通过模拟输入参数或交互式输入来验证。
   - 对于**Web 服务**：使用 `curl` 或浏览器自动化工具（如 Playwright）发送请求并检查响应。
   - 对于**桌面/后台程序**：检查日志输出、生成的文件、数据库变更等副作用。

3. **异常场景覆盖**（仅对于非MVP项目进行测试）：
   - 故意输入错误格式的数据，检查程序是否优雅处理（而非崩溃）。
   - 模拟网络超时、文件不存在等边界情况。

#### 第三阶段：结果评估与报告
1. **对比预期与实际**：
   - 将每个用例的实际结果与预期结果进行比对。
   - 标记状态：✅ **通过** / ❌ **失败** / ⚠️ **部分通过** / ⏸️ **无法执行**。

2. **生成测试报告**：
   - 使用清晰的结构输出报告，包含：
     - 测试摘要（总计/通过/失败数量）。
     - 每个用例的详细执行情况。
     - 失败用例的错误日志或异常截图（如适用）。
     - 针对失败原因的初步分析建议。

3. **提供修复建议**（仅当存在失败用例时）：
   - 根据错误日志，检索并指出可能出错的代码模块或逻辑分支。

### ⚠️ 特殊注意事项（Agent 必须遵守）

- **环境隔离**：测试应在独立的进程中运行，避免干扰正在开发中的代码状态。
- **幂等性**：测试用例应尽可能设计为可重复执行（例如使用固定的测试数据）。
- **网络依赖**：如果程序依赖外部 API，测试时应优先使用 Mock 数据或测试环境凭证。
- **日志保留**：将所有测试输出和错误日志保存到 `./test-results/` 目录下，便于用户回溯。
