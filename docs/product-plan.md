# Select2Explain 产品规划

## 1. 项目定义

### 1.1 一句话定义

Select2Explain 是一款面向桌面办公与阅读场景的 AI 划词解释工具。用户在任意应用中选中某个词、短语或一段描述后，可以通过快捷键或轻交互触发解释请求，系统会结合附近上下文生成 Prompt，并在鼠标停止位置附近弹出临时窗口返回 AI 解释结果。

### 1.2 核心价值

- 解释“在当前语境下是什么意思”，而不是只给静态词典释义
- 将获取解释的动作压缩到单次划词和一次停留，不打断当前工作流
- 统一服务于文档阅读、代码阅读、写作、客服、产品设计、运营分析等需要语义理解的场景

### 1.3 目标平台

- macOS 13+
- Windows 10/11

首发不考虑移动端与 Linux。

## 2. 目标用户与典型场景

### 2.1 目标用户

- 高强度阅读英文或专业资料的知识工作者
- 需要频繁理解陌生术语、缩写或模糊描述的产品、开发、运营人员
- 希望快速获得“上下文解释”而非跳转搜索的 AI 重度用户

### 2.2 典型使用场景

1. 用户在网页文章中选中一个专业术语，触发解释，悬浮窗返回“该术语在这篇文章语境下的含义”。
2. 用户在代码编辑器中选中一段注释或变量命名，触发解释，悬浮窗返回语义推断和上下文说明。
3. 用户在 IM、邮件或 PR 描述中选中一句含糊表达，触发解释，悬浮窗返回可能意图、关键上下文和更直白的说明。

## 3. 产品边界

### 3.1 MVP 必做

- 全局快捷键触发解释
- 读取选中文本或基于剪贴板兜底获取文本
- 捕获有限上下文并组装 Prompt
- 请求云端 AI 接口并返回结果
- 在鼠标附近显示临时悬浮窗
- 支持固定解释、关闭解释、重新解释
- 支持配置 API Key、Base URL、模型名称
- 基础历史记录

### 3.2 MVP 不做

- 自动在所有应用中无感知监听选区变化
- 本地大模型推理
- 复杂团队协作与账户体系
- 多轮对话式侧边栏
- OCR 主流程依赖

OCR 可以作为后续增强功能，仅用于无法直接获取文本的截图场景。

## 4. 功能设计

### 4.1 主链路

1. 用户在任意应用中选中文字或描述
2. 用户按下全局快捷键，例如 `Option + Shift + E` 或 `Alt + Shift + E`
3. 应用尝试读取当前选中内容
4. 应用收集可用上下文
5. 应用构造 Prompt 并向 AI Provider 发起请求
6. 在鼠标当前位置旁展示临时窗口
7. 用户可复制结果、固定窗口、再次解释或关闭

### 4.2 上下文采集策略

为了保证跨平台稳定性，MVP 使用分层策略：

- 第一层：直接读取用户选中的文本
- 第二层：若系统无法直接获取选区，则引导用户通过快捷键把选中内容复制到剪贴板
- 第三层：附带最近一次触发前的用户输入来源信息，例如应用名、窗口标题、时间戳
- 第四层：后续版本再考虑 Accessibility API、OCR 与宿主应用插件协作

### 4.3 AI 返回内容结构

默认结果包含以下模块：

- 核心解释：这个词或这段话在当前语境下是什么意思
- 上下文依据：AI 为什么这样判断
- 更直白表达：适合直接理解的自然语言改写
- 可选延伸：相关术语、风险歧义、使用建议

### 4.4 弹窗交互

- 默认是轻量临时窗，失焦后可自动隐藏
- 支持固定为停靠小窗，便于边看边读
- 支持复制结果
- 支持“重新解释”为更简洁、更专业、更适合初学者等风格

## 5. 非功能要求

### 5.1 性能

- 快捷键触发到弹窗出现小于 300ms，不含 AI 网络耗时
- AI 响应等待期间要立即展示 loading 状态
- 常驻后台内存占用控制在较低水平

### 5.2 可用性

- 用户首次安装后，必须有明确的系统权限引导
- 当无法读取选区时，必须给出可恢复的 fallback 提示
- 当 AI 请求失败时，必须支持重试和查看错误原因

### 5.3 安全与隐私

- API Key 本地安全存储
- 明确提示用户：发送给 AI 的内容可能包含选中文本与有限上下文
- 默认不上传完整屏幕内容
- 历史记录支持一键清空

## 6. 差异化定位

相较传统词典，Select2Explain 更强调“语境解释”；相较纯聊天助手，它把入口嵌入到用户当前阅读位置，不要求先切换到独立对话界面。

## 7. 风险与约束

### 7.1 关键技术风险

- macOS 与 Windows 对跨应用选区读取的能力不一致
- 某些应用内文本无法直接通过系统接口拿到
- 鼠标附近悬浮窗需要处理多屏、缩放比和焦点穿透问题
- 云端模型响应速度直接影响用户体感

### 7.2 规避策略

- MVP 以“快捷键 + 选中文本/剪贴板”作为稳定主链路
- 高级上下文采集作为增强能力，避免首版过度依赖系统辅助功能
- Provider 层抽象，避免模型供应商绑定

## 8. 成功指标

### 8.1 MVP 指标

- 首次成功解释完成率
- 解释触发成功率
- 从触发到看到结果的总时长
- 每日活跃用户的平均触发次数
- 用户手动重试率与错误率

### 8.2 定性反馈

- 用户是否认为结果“比传统翻译更懂上下文”
- 用户是否愿意在阅读/写作流程中长期常驻使用

## 9. 版本愿景

### Phase 1

- 支持 Prompt 模板
- 支持结果风格切换
- 支持固定面板查看历史

### Phase 2

- OCR 截图解释
- 支持截图区域上下文
- 支持更丰富的宿主应用适配

### Phase 3

- 支持团队知识库或企业术语库
- 支持本地模型和离线解释模式
