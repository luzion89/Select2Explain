# Select2Explain 产品规划

## 1. 产品定义

### 1.1 一句话定义

Select2Explain 是一款后台常驻的 AI 划词解释工具。用户在任意桌面应用中用鼠标选中一段文本后，系统自动采集必要上下文，并在鼠标右上方弹出轻量对话框返回解释。

### 1.2 核心价值

- 入口足够轻：没有额外快捷键动作，选中即触发。
- 解释足够准：不是只看孤立词，而是按“选中文本 + 当前窗口上下文”来解释。
- 打断足够少：结果直接在阅读位置附近出现，点空白处就消失。

### 1.3 当前平台策略

- Windows 10/11：当前 MVP 实现平台。
- macOS：只保留设计方案和接口分层，不在本轮作为交付承诺。
- Linux、移动端：不进入 MVP。

## 2. 目标用户与场景

### 2.1 目标用户

- 高频阅读技术文档、网页文章、PR、邮件的知识工作者。
- 需要快速判断一句话在当前上下文里真正含义的开发、产品、运营人员。
- 不想在浏览器、翻译软件、聊天窗口之间来回切换的 AI 重度用户。

### 2.2 典型场景

1. 用户在浏览器文章里选中一个术语，popup 解释该术语在当前文章中的含义。
2. 用户在 IDE 里选中一段变量名或注释，popup 返回语义解释和上下文说明。
3. 用户在 IM 或邮件里选中一句含糊表达，popup 给出更直白的解释和潜在语义。

## 3. MVP 边界

### 3.1 MVP 必做

- 系统托盘常驻，主窗口关闭后不退出。
- 后台自动监听新的文本选区。
- 采集当前选中文本。
- 采集当前前台窗口截图。
- 在截图不足时，再补发窗口全文给模型。
- 在鼠标右上方显示无边框 popup。
- popup 失焦后自动隐藏。
- 支持配置 Base URL、文本模型、视觉模型和 API Key。
- 提供“选区探测”和“完整采集”调试入口。

### 3.2 MVP 不做

- 剪贴板兜底主流程。
- 本地模型推理。
- 历史记录、收藏、固定窗、多轮对话。
- OCR 主流程。
- 团队协作、账号体系、同步。

## 4. 核心交互

### 4.1 主链路

1. 用户打开应用并完成配置。
2. 用户开启“自动监听”，应用转入后台常驻模式。
3. 用户在任意前台应用中选中一段文本。
4. 后端先抓取选中文本、窗口截图、窗口元信息。
5. AI 用“选中文本 + 截图”判断是否已有足够上下文。
6. 若不足，再补发窗口全文。
7. popup 在鼠标右上方展示解释。
8. 用户点击任意其他位置，popup 自动隐藏。

### 4.2 上下文采集原则

- 最小必要原则：先发选区和截图，不直接发完整窗口文本。
- 延迟升级原则：只有截图不足时才补发全文。
- 来源透明原则：始终记录来源应用名、窗口标题、延迟等调试信息。

### 4.3 popup 交互要求

- 默认无边框、置顶、跳过任务栏。
- 首次显示位置跟随鼠标，并做屏幕边界裁剪。
- 不能长时间遮挡用户当前阅读区域。
- 失焦即隐藏，不需要用户额外关窗。

## 5. 非功能要求

### 5.1 性能

- 本地采集动作应在约 1 秒内完成，不包含云端 AI 耗时。
- 后台监听需要避免重复触发相同选区。
- 应用需保持轻量，适合长期托盘驻留。

### 5.2 可用性

- 配置页必须能明确看到“监听是否开启”和“Key 是否已配置”。
- 当采集失败或 API 未配置时，popup 应给出可读错误，而不是静默失败。
- 托盘菜单必须能重新打开控制面板。

### 5.3 安全与隐私

- API Key 必须存系统安全存储，不落磁盘明文。
- 默认不直接发送完整窗口文本。
- 需要在文档里明确告知：截图和必要的窗口文本可能被发送给 AI Provider。

## 6. 风险与策略

### 6.1 当前风险

- Windows 跨应用文本采集依赖 UI Automation，部分应用暴露能力不一致。
- 某些窗口的全文采集质量可能低于截图理解质量。
- popup 位置需要兼顾多屏和 DPI 缩放。
- 部分 Windows 宿主不会稳定暴露可访问选区，可能表现为“前台窗口可识别，但选中文字拿不到”。

### 6.2 对应策略

- 当前 Windows 实现改为 Rust 进程内原生 WinAPI + UI Automation + GDI 路径，避免额外 PowerShell 子进程和脚本执行策略问题。
- 通过“截图优先，全文按需补发”减少对全文采集质量的依赖。
- 对选区签名做去重，避免同一选区重复打扰用户。

## 7. 成功指标

- 有效选区触发率。
- popup 成功展示率。
- 从选区出现到拿到解释的总时长。
- 错误 popup 的占比。
- 用户是否认为解释比传统翻译更贴近当前语境。

## 8. 后续方向

### Phase 2

- popup 内加入复制、固定、重新解释。
- 允许切换解释风格，例如更简洁、更专业、更适合初学者。
- 增加历史记录和收藏。

### Phase 3

- 引入 OCR 作为少数应用的补充能力。
- 支持更丰富的宿主适配。
- 评估本地模型和企业知识库扩展。
