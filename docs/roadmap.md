# Select2Explain 实施路线图

## 1. 项目阶段划分

### Phase 0：规划与验证

目标：

- 明确产品边界
- 确认技术路线
- 输出架构文档和任务拆解

交付物：

- 产品规划文档
- 技术架构文档
- 路线图文档

### Phase 1：技术原型

目标：

- 验证跨平台最小链路是否成立
- 验证悬浮窗显示、快捷键触发、文本获取、AI 调用是否可稳定联动

必须完成：

- Tauri 工程初始化
- 托盘与后台常驻
- 全局快捷键
- 鼠标坐标获取
- 临时悬浮窗原型
- 选中文本读取主链路
- AI API 打通

退出标准：

- 在 macOS 和 Windows 上都能完成最小闭环

### Phase 2：MVP

目标：

- 做出可日常使用的首版

功能范围：

- 设置页
- Provider 配置
- 历史记录
- 解释结果复制
- 解释结果固定/关闭
- 错误提示与重试
- 权限引导

退出标准：

- 非开发用户可以独立安装并完成首次解释

### Phase 3：体验增强

目标：

- 提升解释质量与触发成功率

功能范围：

- Prompt 模板
- 解释风格切换
- 宿主应用上下文增强
- 更完善的窗口定位与动画

### Phase 4：高级能力

功能范围：

- OCR 截图解释
- 本地模型支持
- 知识库与术语库
- 团队配置同步

## 2. 建议排期

如果由 1 名全栈开发主导，建议按以下节奏推进：

1. 第 1 周：工程初始化、架构骨架、基础 UI、配置模块
2. 第 2 周：快捷键、托盘、悬浮窗、窗口定位
3. 第 3 周：文本获取主链路、Prompt 模块、AI Provider
4. 第 4 周：历史记录、错误处理、权限引导、联调
5. 第 5 周：macOS/Windows 回归与体验打磨

如果有 2 人并行开发，可以拆分为：

- 桌面与原生能力
- 前端界面与 AI 业务链路

## 3. 任务拆解建议

### 3.1 桌面基础设施

- 初始化 Tauri 2 项目
- 建立命令通信机制
- 接入托盘
- 接入全局快捷键
- 接入窗口管理

### 3.2 数据与配置

- 设计 SQLite schema
- 接入配置文件管理
- 接入密钥安全存储

### 3.3 AI 链路

- 设计 Prompt 模板
- 定义 Provider 接口
- 实现 OpenAI 兼容 Provider
- 实现请求重试与超时处理

### 3.4 用户体验

- 首启向导
- 权限检测
- 失败回退提示
- 加载状态与流式显示预留

## 4. 关键里程碑

### M1：可弹窗

- 快捷键后可在鼠标附近弹出空白窗

### M2：可解释

- 选中文本后可收到 AI 返回结果

### M3：可稳定使用

- 配置、重试、历史、权限引导全部可用

### M4：准备内测

- 双平台基础回归通过
- 已知问题可控

## 5. 开发前检查清单

- 是否确定 Tauri 2 为正式路线
- 是否明确 AI Provider 首发供应商
- 是否确定首发快捷键默认值
- 是否明确历史记录保留策略
- 是否确定 API Key 的安全存储方案
- 是否明确 macOS 权限引导文案
- 是否明确 Windows 安装包分发方式

## 6. 实施建议

不要一开始就追求“任何应用都能直接读取选区”。这会迅速把项目变成系统兼容性工程。更合理的路径是先做稳定主链路，再逐步扩大宿主应用覆盖范围。
